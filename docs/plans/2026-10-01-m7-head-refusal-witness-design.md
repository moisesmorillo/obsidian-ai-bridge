# Proposed M7 head-CAS refusal witness

**Status: design history; the bounded exception is now normative in the M7 specification and ADR 0017 for isolated implementation.** The initial independent review (2026-10-01) blocked an unbounded second target PUT, receipt authority and resource limits. A corrective review closed the specific orphan-claim false-abort race after requiring the current exact claim and same-generation journal CAS. The production contract is the M7 spec/ADR, not this historical design record. No runtime behavior, current writer or deployed service has changed. Implementation must prove the 64-call cap and receipt recovery tests; Workers Free CPU qualification and deployment remain separately gated.

## Decision to review

After a claimed `write_head` CAS is definitely refused, the claim owner may be unable to advance the just-written operation journal because R2 throttles writes to that key. A fresh resumer sees `attempting` plus a competing head, but cannot infer whether its claimed head write was applied and later superseded. It must return `effect_unknown` and keep the lane blocked. Preserve this fail-closed behavior unless a new immutable receipt can prove a **particular attempted target PUT did not apply** and that no older claimed PUT remains able to apply.

**Conditional candidate, requiring an approved spec exception:** a private create-only *refusal receipt* at one canonical key per `(vaultId, operationId)` under a newly specified **Worker-private** key family. The claim owner may create it after a preflight refusal without dispatch or, only if the exception is accepted, an R2 conditional `put()` returning `null` for that exact original predicate. The latter invocation may send one claimed head PUT **and** one create-only receipt PUT, but never an event PUT or a second head PUT. The receipt is evidence of that one head call's no-effect result, not a second attempt at the head. An observed competing head after a lost/uncertain response is **not** a qualifying refusal. Cloudflare's Workers R2 reference says a failed `put` condition returns `null`, not an R2 object; its contract is the basis for treating the response as definite no-effect ([reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#conditional-operations), retrieved 2026-10-01). If a result's source is ambiguous, do not create a receipt. The existing generic `refused` adapter result conflates preflight and post-`null` read-back; a typed provenance boundary is required before implementation.

## Minimum authority and recovery contract

| Boundary | Required evidence / action |
| --- | --- |
| Eligibility | `write_head` journal contains this invocation's exact `attempting` claim at **generation 1**. It is still current; original key, target bytes, create-only/ETag predicate, request, position, and lane marker validate. A generation >1 is ineligible without a separate proof that *every* earlier dispatched claim cannot still apply. |
| Refusal | No head PUT was dispatched after a verified preflight mismatch, or the single claimed conditional PUT returned `null`. A 429, exception, lost response, divergent target read-back, or a post-success overwrite supplies no refusal receipt. Re-read the currently linked competing head and stale parent; absent/unavailable/own-target evidence is insufficient. |
| Receipt | An immutable **schema-v1 private record** with strict closed fields: `schemaVersion: 1`, `protocolMajor: 1`, `vaultId`, `operationId`, `claimId`, `generation: 1`, `headKey`, `headTargetSha256`, `headPrecondition` (original absent or exact prior ETag/bytes/upload time), `lane`, `sequence`, `refusalSource` (`preflight_no_dispatch` or `conditional_null`), `competingHead` (exact observed ETag, bytes and upload time). The target digest is computed from the canonical intended head bytes; the competitor's typed linked record is revalidated on resume. Reject additional fields, invalid ids/times/ETags, noncanonical keys or bytes, mismatched journal identities, and bodies > **8,192 UTF-8 bytes** before allocating the body. One canonical private key per operation: `${syncOperationKey(vaultId, operationId)}` with `.json` replaced by `.head-refusal.json`; the Worker key builder reconstructs this exact shape and vault prefix, while the public protocol key builders remain unchanged. The publication facade alone creates via `If-None-Match: *`; it validates that the observed journal still contains this exact generation-1 claim before dispatch and exactly reads back a lost response. An existing exact receipt may be reconciled, but only after all journal/lane/head checks; divergent/unavailable never means absent. **Trust limit:** claim ID is visible in R2 and not a signature; this assumes only the authorized Worker can PUT the private key family. A privileged out-of-band writer able to forge a well-typed receipt is outside this authority model unless a separately approved signing-key/rotation protocol is added. |
| Resume | Read exact journal, lane pending marker, receipt, and current linked head. The **currently persisted pending `write_head` journal must still contain the receipt's exact generation-1 `attempting(claimId, generation, claimedAtEpochMs)`** for the same original step/key/precondition, immutable request and reservation. A `retry_wait`, a newer claim/generation, next step, terminal state or unavailable journal is ineligible even if the receipt bytes match. Verify receipt's original predicate and the present stale competing linked head. The current linked head must still match the receipt's exact competing-head observation; otherwise fail closed. After journal cooldown, CAS that **same observed journal generation and ETag** to fixed `create_event` **aborted** intent/time; a lost CAS response must be exactly reread, never treated as success from the receipt alone. If a concurrent resumer changed the journal between verification and CAS, refuse/unknown and do not retry using a refreshed journal ETag. Do not write the event or lane in this invocation. Any missing/divergent evidence returns `effect_unknown` and retains the lane blocker. |
| Success/failure | A receipt is not a lease and does not cancel any PUT. It proves no dispatch or a particular conditional call's `null` result only; therefore generation-1 eligibility excludes earlier target PUTs. Creation and abort-journal CAS are not atomic: the receipt remains inert unless the exact same current `attempting` claim is still present and its observed journal ETag wins the abort-step CAS. Another resumer's later `retry_wait` or claim makes the receipt ineligible; never adopt an orphan receipt. If the receipt write is refused, throttled, unknown without exact read-back, or interrupted before applying, the operation can remain blocked as `effect_unknown`; no guaranteed eventual abort is claimed. |

This receipt is **not** a user-visible feed event or a new public protocol version. It is not an alternate terminal journal or permission to rebase the head's original ETag. The operation cannot release its lane until the existing exact abort event, terminal journal, and lane commit checks pass. Any later same-key head ABA/ETag reuse or noncooperating writer invalidates an argument that older in-flight writes are harmless; this proposal does not cover such an execution beyond the generation-1 no-older-call restriction. Independently verify that `null` is a definitive failed condition, rather than inferring it from a later read.

## Resource envelope and compatibility questions

The accepted attempt path estimates **37–41 R2 GETs and ≤3 PUTs** for one worst mutation invocation (M7 post-journal attempt authority). A code-derived **incremental successful receipt create** uses a marker GET, receipt preflight GET, conditional PUT and exact read-back GET: **+3 GET/+1 PUT** (`sync-r2-object.ts` and `sync-r2-publication.ts`). One explicit journal/lane proof read is marker + record GET: **+2 GET**. Adding only those to the accepted estimate yields **42–46 GETs and ≤4 PUTs**; each additional distinct proof read adds two GETs. This is **not an aggregate maximum**: uncertain responses, refusal, resumed verification and failure paths are not all counted. To make the design enforceably bounded, propose a **64-R2-call mutation-invocation cap** at the one-key object boundary, including marker reads, preflights, conditional writes, read-backs and receipt proofs. Calls past the cap must not be dispatched; exhaustion returns `effect_unknown` with the lane blocker retained. All reads and writes in `mutate`/`resumeOperation` share one new invocation-scoped counted capability (not a process-global counter). A step must reserve its required next target write/read-back allowance before dispatch so the cap cannot silently truncate proof into success. No retry loop or cross-invocation reset of durable floors is permitted. This is a proposed contract, **not existing code**: implementation must instrument nested calls and test every head/receipt success, refusal, lost-response and cap-exhaustion path, proving no invocation exceeds 64. At most four PUTs is the proposed upper limit for this exceptional path (claim journal + head + private receipt + at most one journal transition); the receipt path never writes an event. Until those counters and local workerd behavior are verified, it is not Workers Free or 10-ms-CPU qualified.

**Retention policy proposed:** one immutable receipt per operation, ≤8,192 body bytes, kept for the same lifetime as the operation journal, which M7 does not delete. M7 performs **no receipt cleanup**; neither an expired cursor nor a later lane generation makes it safe to delete a receipt still needed by journal recovery. With N qualifying first refusals, extra retained body bytes are ≤8,192 × N, plus key/metadata; successful extra Class A writes are ≤N. This is intentionally linear, not a finite lifetime storage cap (the existing journal is also retained without a cleanup protocol). If account storage/write quota or 64-call cap prevents receipt persistence, fail closed as `effect_unknown` and keep the lane blocker; no promise of eventual recovery at quota. Operators must monitor storage and Class A usage before any future activation. A finite per-vault quota or deletion/reaping policy would require separately approved authority and cannot be invented by the isolated M7 store. The existing canonical key allowlist, family-size limits, inventory exclusion, and no-cross-vault access must be revised explicitly. Workers Free's documented 10 ms CPU and internal-service subrequest ceilings (1,000) remain unqualified; external subrequests have a separate 50/request limit. These figures and R2's same-key one-write/second throttle are from [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) and [R2 limits](https://developers.cloudflare.com/r2/platform/limits/), retrieved 2026-10-01. No real-vault or live Workers Free qualification is implied.

## Counterexamples and required tests

1. First-generation PUT returns `null`, journal CAS is rate-limited, receipt create succeeds, invocation dies: fresh resumer validates original claim, exact receipt, stale competitor, then advances abort step after cooldown without a head or event PUT in that invocation.
2. Same history but receipt PUT/response/read-back unavailable or divergent: return `effect_unknown`, lane pending; no event PUT.
3. Head PUT responds 429, throws or loses response; competitor appears: do **not** produce a receipt or infer abort, even if stale.
4. Generation 2 or older request still in flight; latest request returns `null` against a competitor: refuse receipt-based abort; a late earlier request may yet apply. Same check after a prior attempt's uncertain response.
5. Receipt exists with wrong claim, target digest, predicate, lane, timestamp, vault or competitor; or current head is owned, now-valid, unreadable or detached from linked version/body: `effect_unknown` and no event/journal terminalization.
6. Two same-ID resumers race: after a definite first-claim refusal but before receipt create/abort CAS, a second resumer advances the journal to `retry_wait` or a newer claim. The old claim owner may leave an inert receipt, but recovery must reject it against the newer current journal and the old ETag must lose; no abort event/head write/terminal result. Same exact receipt bytes may reconcile only while the **original current claim** still matches. Fixed event time/intent remains immutable.
7. A preflight competitor and own head target race under the original ETag, including identical-byte ABA: assess whether R2's ETag semantics and the one-lane writer boundary suffice; if not, restrict to direct `null` and document the remaining unknown case.
8. Resumed event PUT is throttled or has lost response: retain the existing claim and fixed floor; **do not** expect the head-write invocation to PUT both head and event.

## Readiness gate

The initial feasibility review blocked the proposed second target PUT under the former M7 invariant. The owner subsequently instructed completion with the bounded exception, now recorded in M7/ADR 0017; the corrective reviewer closed the orphan-claim race only after requiring a current exact claim and same-generation journal CAS. The 64-call counter, exclusive-Worker binding, permanent linear storage and fail-closed quota behavior still require implementation and operational evidence. **Conditional design review is not code approval, a green test suite or live Workers Free qualification.** Do not weaken the current 3/1,726 failures merely to report a green suite.
