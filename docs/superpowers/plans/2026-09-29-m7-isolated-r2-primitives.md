# M7.3 Isolated R2 Primitives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add tested, uncomposed R2 persistence primitives for protocol-major-one sync current/version/recovery records and inventory scratch records without exposing a sync route or claiming a functioning `SyncStore`.

**Architecture:** Keep the M7.1 key codec in `packages/protocol` and M7.2 policy/port in `packages/core`. A private `apps/worker/src/infrastructure/sync/` boundary validates persisted records and owns conditional R2 reads/writes, exact ETag evidence, cooldown and read-back. Higher-level single-object facades provide version/head/recovery and inventory scratch access for M7.4; they do not sequence an operation, complete a scan, or implement the nine-method `SyncStore` port. No current Worker composition references them.

**Tech Stack:** Strict TypeScript, existing Zod 4 and R2 binding subset, Vitest, Miniflare/workerd, canonical mise tasks. No new dependencies or production bindings.

**Spec:** `docs/milestones/m7-versioned-sync-protocol-and-r2-store.md` (M7.3 only); `docs/decisions/0016-bidirectional-vault-sync.md` is proposed future product direction, not activation authority. M7.1/M7.2 are already merged on `main`.

- User explicitly authorized **one M7.3 PR**, even if it crosses the AGENTS.md 10-production-file / 1,500-net-production-line thresholds. This exception covers only M7.3, not M7.4 or unrelated cleanup; record actual count and rationale in the PR. - Use only `sync/v1/vaults/<validated-vault-id>/` and M7.1 canonical key builders; never scan/adopt/mutate `vault/` or `recovery/` v2 objects. No R2 native DELETE, generic unconditional PUT, public HTTP/MCP, plugin change, deployment, personal-vault use, or production vault provisioning. Tests seed a marker in isolated synthetic storage.
- Strict protocol-major-1 storage records: reject wrong vault/path/key, unknown fields/major, malformed UUIDv4/revision, invalid UTF-8, oversize bodies and inconsistent hash/byte size. Markdown content ≤1 MiB; canonical path ≤720 UTF-8 bytes; head ≤2,048 bytes. Enforce manifest ≤8,192 bytes, raw R2 cursor ≤4,096 bytes, chunk ≤12 KiB, envelope ≤8,192 bytes and head summary ≤1,536 bytes where applicable. If a field's representation is not yet fully specified by M7, choose an adapter-private strict schema compatible with the M7 bounds; record the choice and do not silently change a completed public contract.
- Create-only writes use R2 `If-None-Match: *`; replacements use only the ETag captured from the exact read of that key. Missing ETag, uncertain effect, rate-limit response, stale predicate or invalid record never become success or refreshed-CAS retry. An exact read-back may prove a write; an unavailable/divergent read-back remains unknown. Every repeated write attempt to the same key observes ≥1,100 ms after the last successful R2 `uploaded` time or the later 429/timeout observation; return a typed safe retry time without sleeping in a Worker. No local lock is a correctness mechanism.
- M7.3 tests single-object primitives, isolation and local workerd conditional behavior, **not** multi-key atomic mutation, journal/feed sequence, stable-vector scan, cleanup, full `SyncStore` conformance or Workers Free CPU qualification. Leave those for M7.4. Never claim inventory completion or absence from scratch records.
- Every named production semantic declaration gets useful TSDoc. Strong types, alias imports, no `any`/unchecked casts/deprecated APIs/direct console. Tests outside `src/`; no extra dependency or runner. Keep M1–M6 regression behavior intact.
- Execute in one isolated branch/worktree with one writer at a time. Use explicit `model: "openai-codex/gpt-6-luna:high"` for each Pi subagent implementer/reviewer after verifying the exact provider/model and thinking suffix at launch; fail closed rather than substitute a model. Supervisor handles task briefs, rulings and final PR authority; no child spawns its own agents. No push/PR creation until checks, semantic review and explicit handoff acceptance.

## Review Focus

1. A malformed or cross-vault persisted head/recovery record must not be returned as a valid current/recovery observation (Tasks 1 and 3).
2. A timed-out create followed by a missing/unavailable read-back must not trigger an unsafe different-byte retry or claim absence (Task 2).
3. Two concurrent exact-head CAS writers must not both report confirmed success; a refused predicate cannot refresh and replace the winner (Tasks 2 and 3).
4. An inventory chunk that exists but does not match its key, cursor digest or prior hash cannot advance the manifest; M7.3 must only expose validated storage evidence for M7.4 to interpret (Tasks 1 and 4).
5. Synthetic v2 sentinel objects must stay byte-for-byte identical and never be listed by sync-prefix calls, even on error and retry (Task 4).

### Task 1: Strict private persistence contracts

**Files:** Create `sync-record.schemas.ts`, `sync-record.codec.ts`, `sync-record.types.ts` and `sync-record-codec.test.ts` from the file map. Do not modify public M7.1 schemas without an evidenced contract defect.

**Interfaces:** Export `decodeSyncRecord(kind: SyncRecordKind, key: string, bytes: Uint8Array, expectedVaultId: SyncVaultId): SyncDecodedRecord` and `encodeSyncRecord(record: SyncDecodedRecord): Uint8Array` from the codec, with a closed `SyncRecordKind` for vault marker, head, version, content metadata/body, recovery metadata/body, active slot, manifest and chunk. If body records require bytes rather than JSON, use a discriminated record with exact `Uint8Array` and independently verified metadata; never text-decode Markdown permissively. The codec consumes M7.1 `sync*Key` builders and strict UUID/path schemas, and never exposes an R2 ETag or cursor through core. Define storage limits in one authoritative constant object in this module family. A persisted record binds vault/path/revision/operation where applicable; chunk carries step, prior hash, cursor digest and exact encoded output cursor for later replay verification.

### Task 2: One-key conditional R2 evidence boundary

**Files:** Create `sync-r2-object.ts`, `sync-r2.types.ts`, `sync-r2-object.test.ts`, `sync-r2-primitives.test.ts`; change existing `r2.types.ts` only if the existing delete-free conditional binding cannot express the required exact read/list/write.

**Interfaces:** Export `SyncR2ObjectStore` with `read(key: SyncR2Key, maxBytes: number): Promise<SyncR2ReadResult>`, `create(key: SyncR2Key, bytes: Uint8Array): Promise<SyncR2WriteResult>` and `replace(observed: SyncR2Observed, bytes: Uint8Array): Promise<SyncR2WriteResult>`. `SyncR2Key` is an adapter-private branded string produced only by validating one M7.1 key builder result; `SyncR2Observed` is adapter-private and binds key, exact ETag, body and `uploaded`; `SyncR2ReadResult` distinguishes verified absent, observed, unavailable. `SyncRecordRead<T>` and `SyncRecordObservation<T>` are typed projections of that read result, retaining the exact private ETag only within `apps/worker/src/infrastructure/sync/`. `SyncR2WriteResult` distinguishes confirmed (exact read-back), refused, throttled (`retryAfterEpochMs`) and effect_unknown (optional safe retry time); do not infer a confirmed commit solely from a timed-out PUT. Inject an epoch clock for deterministic cooldown tests; isolate R2 response classification behind this boundary. All accepted keys must start with a validated vault prefix and equal an allowed M7.1 key shape; no free-form caller key.

## Self-review boundary

This plan implements M7.3 storage primitives, not a complete `SyncStore`: a caller cannot publish a mutation, sequence/feed event, complete an inventory or recover an interrupted journal through these modules. That separation protects the M7.4 responsibility and prevents tests of a single-object fake or local workerd from masquerading as end-to-end correctness. Preserve an explicit typed refusal or no API rather than a placeholder `SyncStore` implementation returning misleading success.
